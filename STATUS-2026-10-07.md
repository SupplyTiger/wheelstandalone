**1. What wheel data does the standalone actually store?**
`the-wheel`: one manual snapshot (2026-09-23) — account KPIs, 11 positions
(3 expired since), realized-P&L history, gate stack. `wheelstandalone-local`:
zero wheel state — screener + watchlist only.

**2. How fresh is it?**
Stale (tracker: 2 weeks, with expired contracts still listed) and
contradicted by today's Fidelity pull ($216,667 claimed vs $90,671 actual —
a 2.4x discrepancy). Screener pulls live Yahoo data on demand but persists
nothing. Manually maintained; no feed; no developer.

**3. Can it answer: open positions / per-position rules / what needs attention?**
- Open positions: NO — not for today. Its book doesn't match Fidelity's.
- Per-position rules/triggers: PARTIALLY, and only as of Sep 23 — position
  notes ("DEAD CAPITAL", "Covers 400 shares", "Cash-secured") and mode labels
  (SELL/MANAGE/DO-NOTHING). It never had per-position triggers like
  "roll if X / close at Y%"; its rules are portfolio-level gates.
- What needs attention: it WOULD flag concentration breaches and dead
  capital — against a two-week-old book. Worse than useless for live decisions.

**4. Gaps Fidelity-via-VNC must fill:** everything time-sensitive — current
positions, marks, day/total P&L, expirations, cash/margin, assignment risk.
Fidelity is now the only fresh positions source.

## Recommendation: HYBRID — retire the tracker as a data source, keep the rules + screener

**Do we even need the wheel standalone anymore?** Not as a positions database —
Fidelity-via-VNC (home IP) supersedes it completely and is fresher by
construction. But the standalone still holds things Fidelity never will:

*Keep (unique value):*
- **The gate stack / rules engine** — concentration caps, Rule 6 $4K/mo
  premium target, naked ban, assignment=acquisition doctrine,
  SELL/MANAGE/DO-NOTHING modes, dead-capital concept. Fidelity shows numbers;
  the wheel app encodes *his rules*. This is the durable IP.
- **Wheel KPIs history** — realized premium log, Theta Sniper close rate,
  "+$23K since Jul 30" framing. Fidelity has raw history; the wheel app has
  the wheel-specific scoreboard.
- **The CSP screener** (`wheelstandalone-local`) — pre-trade screening with
  the 5 gates, max pain, earnings blackout. A *new-trade* tool; Fidelity
  can't do this. (Verify its live-data path once from a normal network
  before trusting it.)

*Retire:*
- **`the-wheel/data/positions.json` as a data source.** It is actively
  misleading ($216.7K vs $90.7K). Mark it archived/stale; no agent should
  read positions from it again.

*Costs of the status quo:* staleness hazard (2.4x equity discrepancy),
manual maintenance with no developer, name confusion between the two apps.

**Concrete next step (the thing worth building):** a small importer that
takes a Fidelity positions pull (e.g. `~/workspace/fidelity/positions-2026-10-07.md`)
and renders it through the wheel's gate stack — concentration %, dead-capital
flags, premium banked vs the $4K target, floor headroom. That gives Ryan the
wheel dashboard **on live data** with zero manual sync. The manual
`positions.json` is the thing worth retiring; the rules are the thing worth keeping.
